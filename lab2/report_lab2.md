# Отчёт по лабораторной работе 2: подключение бота-планировщика к данным

## Описание задачи

Бот из лабораторной 1 (Telegram → LLM → TickTick CLI) улучшен: к нему подключены четыре источника данных. Раньше бот только выполнял команды и сразу забывал о них. Теперь он помнит свои действия, знает погоду, умеет обмениваться с пользователем файлами и сам присылает новости.

**Какую проблему решает.** Одного списка задач мало для планирования дня. Нужно понимать, что уже сделано за неделю, как погода повлияет на планы, как быстро загрузить десяток задач из таблицы и вывести их обратно, и не тратить утро на чтение новостей о научных стартапах.

**Подключённые данные.**

|Источник|Тип|Что даёт боту|
|-|-|-|
|SQLite (`bot.db`)|локальная база|история всех действий бота, статистика по проектам, подписки на новости|
|Open-Meteo|публичный API без ключа|погода в любом городе и «План на сегодня»|
|CSV-файлы|файлы пользователя|выгрузка задач в файл и создание задач из присланного файла|
|RSS-ленты (TechCrunch, MIT Technology Review, Singularity Hub, ScienceDaily)|публичные ленты новостей|новости о научных и технологических стартапах на русском, утренний дайджест|

**Новые команды.** `/history \[дни] \[слово]`, `/stats \[дни]`, `/weather \[город]`, `/today \[город]`, `/export \[done]`, `/news \[N]`, `/news\_on \[ЧЧ:ММ]`, `/news\_off`. Те же возможности работают обычными фразами: «Что я делал за неделю?», «Какая погода в Казани?», «Выгрузи задачи в файл», «Что нового у научных стартапов?». Файл CSV достаточно прислать в чат.

**Почему выбраны эти данные.** Они логично продолжают бота-ассистента для задач: история и статистика показывают прогресс, погода и «План на сегодня» помогают планировать день, CSV закрывает массовую загрузку и выгрузку, а новости превращают бота из инструмента в ежедневного помощника. Задачи по-прежнему лежат только в TickTick, бот ничего не копирует в свою базу, кроме журнала своих действий.

## Промпт для LLM

Исходный промпт составлен по шаблону из задания («Улучши моего Telegram-бота, добавив работу с данными»). Ниже финальная версия, с которой создан код.

```text
Улучши моего Telegram-бота, добавив работу с данными: SQLite, публичным API, CSV-файлами и RSS-лентами новостей.

Текущий функционал бота:
Telegram-бот-планировщик на Python (python-telegram-bot). Пользователь пишет задачу обычным текстом, LLM (через OpenAI-совместимый API) превращает фразу в JSON-команду, а бот выполняет её через официальный TickTick CLI. Бот умеет: создавать, менять, переносить в другой проект и завершать задачи (описание, теги, срок, приоритет, напоминание), искать и фильтровать задачи, создавать, переименовывать и удалять проекты (удаление с подтверждением кнопкой), создавать, смотреть и менять привычки. Ограничения: бот отвечает только владельцу (ALLOWED\_USER\_ID), задачи и привычки не удаляет, все ошибки превращает в понятные сообщения.

Новый функционал:
- SQLite (файл bot.db): записывать каждое действие бота (создание, изменение, завершение задач, проекты, привычки, выгрузка) в таблицу actions: user\_id, время (UTC), вид действия, название, проект, детали, исходная фраза пользователя. Команда /history \[дни] \[слово] показывает действия за период (по умолчанию 7 дней) с поиском по слову (в том числе по кириллице без учёта регистра). Команда /stats \[дни] показывает, сколько задач создано, изменено и завершено, и разбивку по проектам.
- Публичный API Open-Meteo (без ключа): команда /weather \[город] показывает текущую погоду и прогноз на сегодня, город находится через Geocoding API. Команда /today \[город] присылает план на сегодня: погода, задачи со сроком на сегодня и просроченные (из TickTick). Ответы API кэшировать на 10 минут. Если API недоступен, /today всё равно показывает задачи.
- CSV: команда /export \[done] отправляет файл с активными (или выполненными) задачами: колонки title, project, due, priority, tags, description, status, разделитель ";", кодировка UTF-8 с BOM. Если пользователь присылает CSV-файл, бот создаёт из него задачи в TickTick. Поддержать разделители ";" и ",", кодировки UTF-8 и Windows-1251, русские и английские названия колонок, форматы дат 2026-10-15 18:00, 15.10.2026 18:00 и 2026-10-15 (без времени - 09:00), приоритеты словами и цифрами. До 50 строк и 200 КБ за раз. Некорректные строки пропускать и перечислять с номерами.
- RSS-новости: команда /news \[N] показывает свежие новости о научных и технологических стартапах из английских RSS-лент (TechCrunch Startups, MIT Technology Review, Singularity Hub, ScienceDaily Technology). Из общих лент оставлять записи с ключевыми словами о стартапах, убирать повторы и записи старше 3 дней, брать не больше двух новостей из одного источника. LLM переводит заголовки на русский и пересказывает суть одним предложением; в сообщении только заголовок, пересказ, источник и ссылка (полные тексты не копировать). Команды /news\_on \[ЧЧ:ММ] и /news\_off включают и выключают утренний дайджест (по умолчанию 08:00): подписка хранится в SQLite (news\_subs), отправленные ссылки тоже (news\_sent), задача ставится через JobQueue и восстанавливается после перезапуска.
- Фразы на естественном языке должны работать так же, как команды: «Что я делал за неделю?», «Статистика за месяц», «План на сегодня», «Какая погода в Казани?», «Выгрузи задачи в файл», «Что нового у научных стартапов?». Для этого расширить системный промпт LLM новыми действиями (history, stats, today, weather, export, news).

Данные:
- SQLite: таблица actions (id, user\_id, created\_at, action, title, project, details, source\_text).
- Open-Meteo: https://open-meteo.com/en/docs (прогноз) и https://open-meteo.com/en/docs/geocoding-api (поиск города).
- RSS: https://techcrunch.com/category/startups/feed/, https://www.technologyreview.com/feed/, https://singularityhub.com/feed/, https://www.sciencedaily.com/rss/top/technology.xml

Требования:

- Хорошие комментарии в коде

- Новый код источников данных вынести в отдельный файл integrations.py

Создай:

1. Обновленный bot.py
2. Файл integrations.py и файл с данными tasks\_example.csv
3. Обновленный README.md, .env.example и requirements.txt
```

### Промпты внутри бота

* **Разбор команд.** Системный промпт `SYSTEM\_PROMPT` в `bot.py` расширен новыми действиями `history`, `stats`, `today`, `weather`, `export`, `news`. Благодаря этому фраза на естественном языке превращается в то же действие, что и команда.
* **Перевод новостей.** Новый промпт `TRANSLATE\_PROMPT` получает список английских новостей и возвращает JSON с русским заголовком и пересказом одним предложением. Он запрещает выдумывать факты и требует оставлять названия компаний латиницей.

## Реализация

Весь код источников данных вынесен в `integrations.py`, `bot.py` только подключает его к командам и к разбору фраз. Модуль не импортирует `bot.py`, поэтому его можно проверять отдельно.

### 1\. SQLite: история и статистика

Таблица `actions` (id, user\_id, created\_at в UTC, action, title, project, details, source\_text). Запись идёт после каждого успешного действия: создание, изменение, завершение задач, проекты, привычки, выгрузка. Поиск в `/history` фильтруется в Python, потому что SQLite не умеет регистронезависимый поиск по кириллице. Запросы параметризованы. Если базу открыть не удалось, бот продолжает работать, а история отключается с понятным сообщением.

### 2\. Open-Meteo: погода

Город превращается в координаты через Geocoding API, затем запрашиваются текущая погода и прогноз на сегодня. Ответы кэшируются на 10 минут, таймаут запроса 10 секунд. `/today` собирает погоду, задачи со сроком на сегодня и просроченные. Если сервис погоды недоступен, задачи всё равно показываются.

### 3\. CSV: выгрузка и загрузка

* **Выгрузка.** Файл с колонками title, project, due, priority, tags, description, status, разделитель `;`, кодировка UTF-8 с BOM (Excel открывает без «кракозябр»).
* **Загрузка.** Автоопределение разделителя `;` или `,`, кодировки UTF-8 и Windows-1251, русские и английские названия колонок, три формата дат, приоритеты словами и цифрами. Лимиты: 50 строк и 200 КБ. Некорректные строки пропускаются, а бот перечисляет их с номерами и причинами. Пример файла: `tasks\_example.csv`.

### 4\. RSS: новости о научных стартапах

* Четыре английских RSS-ленты. Из трёх общих лент оставляются записи с ключевыми словами о стартапах и науке.
* Дубликаты убираются, записи старше 3 дней отбрасываются, из одного источника берётся не больше двух новостей.
* LLM переводит заголовок и пересказывает суть. В сообщении только заголовок, пересказ, источник и ссылка, полные тексты статей бот не копирует.
* `/news\_on 08:00` сохраняет подписку в SQLite и ставит ежедневную задачу в планировщик `JobQueue`. Отправленные ссылки запоминаются, поэтому новости не повторяются. После перезапуска подписка восстанавливается.

### Обработка ошибок

|Ситуация|Что делает бот|
|-|-|
|Сервис погоды не ответил или недоступен|`/weather` сообщает о сбое, `/today` показывает задачи без погоды|
|Неизвестный город|«Не нашёл город»|
|Нет истории за период|«Ничего не найдено»|
|База SQLite не открылась|история отключена, остальное работает|
|CSV: пустой файл, нет колонки `title`, неверная кодировка, слишком большой, не CSV|понятное сообщение, задачи не создаются|
|CSV: плохая дата, приоритет, неизвестный проект|строка пропускается и перечисляется в итоге|
|Часть RSS-лент недоступна|берутся остальные; если не ответила ни одна, сообщение о сбое|
|LLM не перевела новости|приходят оригинальные заголовки с пометкой|
|Неверное время в `/news\_on`|подсказка с форматом ЧЧ:ММ|
|Ошибка LLM-сервиса (модель недоступна, неверный ключ, лимит)|сообщение с подсказкой, что поправить в `.env`|

## Трудности и решения

|Проблема|Причина|Как решили|
|-|-|-|
|Поиск в `/history` по слову «Созвон» не находил «созвон»|`LIKE` в SQLite не игнорирует регистр для кириллицы|фильтрация по слову сделана в Python через `casefold()`|
|CSV из русского Excel открывался с «кракозябрами» или не читался|Excel сохраняет в Windows-1251 с разделителем `;`, а на выгрузке нужна кодировка с BOM|при загрузке перебираются UTF-8 и Windows-1251, разделитель определяется автоматически; выгрузка идёт в UTF-8 с BOM|
|Сервис погоды может не ответить|внешний API вне нашего контроля|таймаут 10 секунд, кэш на 10 минут, `/today` показывает задачи даже без погоды|
|Источники новостей на английском|выбраны мировые ленты о стартапах|перевод и пересказ через LLM; при сбое LLM приходят оригинальные заголовки|
|Ошибка 404 «No endpoints found for apodex/apodex-1.1-mini:free»|бесплатную модель на OpenRouter убрали|выбрана другая модель в `LLM\_MODEL`; в бот добавлено сообщение «модель недоступна, смените LLM\_MODEL»|
|Ошибка 400 «is a decisions model and cannot be used with chat/completions»|выбрана специальная модель, не предназначенная для чата|нужна обычная chat/instruct-модель; в бот добавлено понятное сообщение об этой ошибке|
|`/news\_on \[21:43]` отвечало «время должно быть в формате ЧЧ:ММ»|квадратные скобки из справки были введены как часть команды|разбор времени теперь игнорирует скобки; в справке и README формат описан явно|

## Выводы

Бот подключён к четырём источникам данных, все новые функции доступны и командами, и обычными фразами, прежний функционал сохранён.

### Что получилось хорошо

* Код источников вынесен в `integrations.py`, `bot.py` остался читаемым; модуль можно тестировать отдельно от Telegram.
* Каждый источник отказоустойчив: сбой погоды, ленты, LLM или базы не ломает бота и превращается в понятное сообщение.
* Данные не дублируются: задачи остаются в TickTick, а в SQLite лежит только журнал действий и подписки.
* Новости копируют только заголовок и ссылку, полные тексты статей не используются.
* Логика покрыта автоматическими проверками (82 штуки).

### Что можно улучшить

* Бесплатные модели нестабильны: их убирают и ограничивают по запросам. Для постоянной работы лучше недорогая платная модель.
* Дайджест приходит только пока бот запущен. Для надёжной работы его нужно развернуть на сервере.
* Фильтр новостей по ключевым словам грубый; можно просить LLM оценивать релевантность.
* Можно добавить другие бесплатные API: курсы валют ЦБ, производственный календарь (isdayoff.ru), восход и закат из Open-Meteo.

### Чему научились

* Подключать к боту разные виды данных: локальную базу, публичный API, файлы и RSS.
* Продумывать отказоустойчивость внешних источников: таймауты, кэш, запасное поведение.
* Работать с кодировками и форматами CSV, которые на практике сильно отличаются от «идеального» файла.
* Читать ошибки внешних сервисов (404, 400) и делать их понятными пользователю.
* Улучшать промпт и существующий проект по шагам, не ломая прежний функционал.
