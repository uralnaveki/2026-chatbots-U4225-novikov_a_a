Отчёт по лабораторной работе 1: Telegram-бот-планировщик для TickTick
Описание задачи
Бот принимает задачу обычным текстом в Telegram и сам кладёт её в нужный список TickTick: подбирает проект, срок, приоритет, теги и напоминание.
Какую проблему решает. Задачи появляются на ходу, а чтобы записать одну в TickTick, нужно открыть приложение, выбрать список, поставить срок, приоритет и напоминание. Бот убирает эти шаги: достаточно написать «Завтра в 10 созвон с клиентом, высокий приоритет, напомни за 30 минут». Ответ подтверждает, что именно сделано: в каком проекте создана задача, на какое время поставлено напоминание, какой установлен приоритет.
Что умеет.
Создавать и менять задачи: описание, теги, срок, приоритет, напоминание, перенос в другой проект, завершение.
Искать и фильтровать задачи по тексту, тегам, приоритету и статусу.
Создавать, просматривать, переименовывать и удалять проекты (удаление только после подтверждения кнопкой).
Создавать, просматривать и менять привычки (без удаления).
Почему выбрана эта задача. Это вариант 3 из задания, «Бот-ассистент для задач»: принимает задачи в текстовом виде, организует их, ставит напоминания. TickTick уже используется для личного планирования (списки «СИСТЕМА», «Жизнь», «Учёба»), у него есть официальный консольный клиент, а Telegram всегда под рукой на телефоне и компьютере. Бот не хранит задачи у себя: единственный источник данных остаётся в TickTick, поэтому ничего не расходится.
Промпт для LLM
```text
Создай Telegram-бота на Python с использованием библиотеки python-telegram-bot.

Функционал бота:
- [принимать задачи в текстовом виде и распределять по спискам/проектам задач в Tick Tick]
- [создать задачу, поставить напоминание, добавить Создавать и редактировать задачи. Можно добавлять задачи с описанием, тегами, сроками, приоритетами и напоминаниями
Работать с проектами. Создавать, просматривать, обновлять и удалять проекты.
Управлять привычками (habits). Поддерживаются операции создания, чтения, обновления (без удаления).
Искать и фильтровать задачи по тексту, тегам, приоритету и статусу.]
- [Задача создана в проекте, поставлено напоминание по задаче " " на (время), установлен новый приоритет и т.д.]
- [данные хранить не требуется]

Требования:
- Бот должен быть простым и понятным
- Код должен быть хорошо прокомментирован
- Использовать файл для хранения данных (JSON или SQLite)
- Добавить обработку ошибок

Создай:

1. Файл bot.py с кодом бота
2. Файл requirements.txt с зависимостями
3. Файл README.md с инструкцией по запуску
4. Файл .env.example для примера конфигурации
```
Промпт внутри бота
Сам бот тоже обращается к LLM: системный промпт в `bot.py` (переменная `SYSTEM_PROMPT`) передаёт модели текущее время, список проектов пользователя и последнюю задачу, а в ответ требует один JSON-объект с действием (`task_create`, `task_update`, `task_search`, `project_create`, `habit_create` и др.) и параметрами. Проект модель выбирает строго из переданного списка, относительные даты вроде «завтра» считает от текущего времени. Бот сам выполняет действие через TickTick CLI и проверяет проект по id, чтобы модель не могла положить задачу в несуществующий список.
Стек технологий
Бот написан на Python 3.10+; четыре внешних библиотеки и официальный CLI закрывают всё остальное.
Компонент	Для чего	Почему выбран
`python-telegram-bot` 21–22	работа с Telegram: команды, текстовые сообщения, кнопки подтверждения	библиотека из задания, асинхронная, хорошо задокументирована
TickTick CLI (`@ticktick/ticktick-cli`, нужен Node.js)	создание задач, проекты, привычки, поиск	официальный клиент TickTick на базе Open API: не нужно самим писать OAuth и HTTP-запросы, вход делается одной командой `ticktick auth login`
`openai`	обращение к LLM, которая разбирает текст пользователя в команду	один клиент работает с любым OpenAI-совместимым сервисом; модель меняется в `.env`, код не правится
OpenRouter, модель `apodex/apodex-1.1-mini:free`	сервис и модель для LLM	единый адрес для многих моделей, есть бесплатные
`python-dotenv`	чтение настроек из `.env`	токены и ключи не попадают в код

`tzdata`	часовые пояса (`Europe/Moscow`)	на Windows без неё Python не знает базу часовых поясов, а сроки задач должны быть верными
`data.json`	маленький файл хранилища: кэш списка проектов и последняя задача	требование задания (JSON или SQLite); для двух полей база данных лишняя
Задачи остаются только в TickTick: бот даёт только удобный вход в Telegram, а вся работа с данными идёт через CLI.
Трудности и решения
Основные трудности были связаны не с логикой бота, а с установкой, запуском на Windows и настройкой LLM.
Проблема	Причина	Как решили
`source .venv/bin/activate` не работает в командной строке	эта команда для macOS и Linux	на Windows использовать `.venv\Scripts\activate`
Node.js и `ticktick` видны только в консоли администратора	обычная консоль не видела обновлённый путь (PATH)	бота запускают из той же консоли, где работает `ticktick` и пройдена авторизация
Бот пишет «команда ticktick не найдена», хотя в консоли она работает	npm создаёт на Windows файл `ticktick.cmd`, а Python без дополнительных действий ищет только `.exe`	в `bot.py` путь к команде находится через `shutil.which`; опасные для `cmd.exe` символы в тексте задачи заменяются пробелами. После этого `/projects` показал список проектов
Ошибка 401 «Missing Authentication header» от OpenRouter	в `.env` не был указан ключ `LLM_API_KEY`	ключ вписан в `.env`; в код добавлена очистка ключа от лишних пробелов и кавычек и диагностическая строка при запуске (длина и начало ключа). После правки `.env` бота нужно перезапускать
Выводы
Получился работающий Telegram-бот, который подключён к TickTick через официальный CLI: команда `/projects` показывает реальные списки пользователя.
Что получилось хорошо
Полный проект (`bot.py`, `requirements.txt`, `.env.example`, `README.md`) создан из одного промпта без написания кода вручную.
Код подробно прокомментирован, ошибки CLI, LLM и сети превращаются в понятные сообщения в чате.
Безопасность: бот отвечает только владельцу (`ALLOWED_USER_ID`), удаление проекта требует подтверждения кнопкой, удаления задач и привычек нет совсем.
Проект для задачи выбирается по смыслу из реального списка проектов, а не выдумывается моделью.
Что можно улучшить
Протестировать на реальных задачах все сценарии (создание с напоминанием, перенос, поиск, привычки): формат напоминаний и ответы CLI подбирались по документации.
Бесплатные модели медленные и иногда не возвращают чистый JSON, для стабильности можно перейти на платную модель.
Бот работает, пока включён компьютер, где выполнен вход в TickTick: для постоянной работы его нужно развернуть на сервере.
Добавить отправку ежедневного списка дел и поддержку голосовых сообщений.
Чему научились
Формулировать промпт по шаблону и дорабатывать его по результатам запуска.
Не доверять ответу LLM без проверки: утверждение про «нет официального CLI» оказалось ошибочным.
