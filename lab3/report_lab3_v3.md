# Отчёт по лабораторной работе 3: запуск бота для реального использования


## Описание деплоя

**Выбранный способ:** Docker (вариант 3 из задания), запуск на локальном компьютере с Windows через Docker Desktop.

**Почему именно этот.**

- Бот работает через polling: он сам опрашивает Telegram, поэтому публичный адрес, ngrok и webhook из вариантов 1 и 2 ему не нужны.
- Бот управляет TickTick через официальный консольный клиент (Node.js), в который нужно один раз войти в аккаунт. Docker-образ упаковывает вместе Python, Node.js и CLI, а вход сохраняется в томе `data/` и переживает перезапуски и обновления.
- Бесплатные облачные платформы (Railway, Render) либо ограничены по времени, либо усыпляют сервис и не хранят вход в CLI между перезапусками.
- `restart: unless-stopped` поднимает бота после сбоя и перезагрузки.

**URL бота:** https://t.me/itmoftmi_na_bot (@itmoftmi_na_bot).

*Скриншот: **[ВСТАВИТЬ скриншот бота в Telegram и окна `docker compose ps` с работающим контейнером]**.*

## Процесс деплоя

### Подготовка кода

- Токены и ключи берутся из `.env`, в репозиторий файл не попадает (`.gitignore`: `.env`, `*.pyc`, `__pycache__/`, `*.db`, `*.log`, `data/`).
- Логирование через `logging` с временем, именем модуля и уровнем сообщений; в Docker логи читаются командой `docker compose logs`, а их размер ограничен (10 МБ × 3 файла).
- Все внешние сбои (TickTick CLI, LLM, погода, RSS, CSV, база) превращаются в понятные сообщения в чате, процесс не падает.
- Для нескольких людей `ALLOWED_USER_ID` теперь принимает список ID через запятую, у каждого пользователя своя «последняя задача», история, статистика и подписка на новости.

### Пошаговая инструкция

1. Установить Docker Desktop.
2. Заполнить `.env` (токен бота, ключ и модель LLM, список ID пользователей через запятую).
3. Собрать образ: `docker compose build`.
4. Войти в TickTick. Вход через браузер внутри контейнера не работает (см. «Проблемы»), поэтому вход выполняется на компьютере: `ticktick auth login`, затем папка `C:\Users\<имя>\.config\ticktick-cli` копируется в `data\home\.config\ticktick-cli`. Проверка: `docker compose run --rm bot ticktick project list --json`.
5. Запустить: `docker compose up -d`; смотреть логи: `docker compose logs -f`.
6. Обновлять после правок: `docker compose up -d --build`.

### Файлы деплоя

| Файл | Назначение |
| --- | --- |
| `Dockerfile` | образ на базе Node.js 20: ставит Python, TickTick CLI и зависимости бота |
| `docker-compose.yml` | запуск с автоперезапуском, `.env`, томом `data/` и ограничением логов |

### С какими проблемами столкнулись

| Проблема | Причина | Как решили |
| --- | --- | --- |
| `failed to connect to the docker API ... dockerDesktopLinuxEngine` при `docker compose build` | Docker Desktop установлен, но не запущен | запустить Docker Desktop и дождаться статуса «Engine running» |
| `failed to calculate checksum ... "/requirements.txt": not found` | в папке, из которой запускалась сборка, не было файла `requirements.txt` | **[проверьте и уточните: файл скопирован в папку проекта]** |
| `OAuth callback timed out` при `docker compose run --rm bot ticktick auth login` | после входа TickTick возвращает браузер на `localhost`, то есть на компьютер, а принимать ответ должен CLI внутри изолированного контейнера | вход выполнен на компьютере, папка `.config\ticktick-cli` скопирована в том `data\home\.config\ticktick-cli`; проверка `project list --json` показала проекты |
| Две команды, вставленные в одну строку, создали лишнюю папку | `mkdir` принял вторую команду как список имён папок | лишняя папка удалена, команды вводятся по одной |
| Примеры из задания (webhook, ngrok, `pandas`, `requests`) не подходят | бот работает через polling, использует `httpx` и не использует `pandas` | выбран деплой без webhook, список зависимостей оставлен рабочим |
| Вход в TickTick нужен внутри контейнера | CLI хранит вход в домашней папке пользователя | `HOME` указан на том `data/home`; в него скопирован готовый вход, он сохраняется между перезапусками |
| Бот был рассчитан на одного пользователя | один `ALLOWED_USER_ID` и общая «последняя задача» | список ID, «последняя задача» теперь у каждого своя |

**Ограничение:** все приглашённые пользователи работают с одним аккаунтом TickTick (владельца), потому что CLI хранит один вход. Проекты и задачи у них общие, а история, статистика и дайджест раздельные.

## Выводы

### Что получилось хорошо

- Бот упакован в Docker: один набор команд запускает его и на компьютере, и на сервере.
- Автоперезапуск, ограничение логов и том с данными дают устойчивую работу без ручного вмешательства.
- Бот доступен нескольким людям одновременно, доступ ограничен списком ID, у каждого свои история и настройки.
- В боте встроены сбор отзывов и статистика использования.

### Что можно улучшить дальше

- У каждого пользователя свой аккаунт TickTick: нужен отдельный вход и отдельная папка настроек CLI на каждого человека.
- Развернуть на постоянном сервере (VPS), чтобы бот не зависел от включённого компьютера.
- Платная стабильная модель вместо бесплатной.
- Голосовые сообщения и ежедневный список дел.

### Чему научились

- Упаковывать бота вместе с внешними зависимостями (Node.js CLI) в Docker и хранить состояние в томе.
- Выбирать способ деплоя по реальным ограничениям проекта, а не по шаблону из задания.
- Превращать одного пользователя в нескольких: списки доступа, раздельное состояние, ограничения общего аккаунта.
- Собирать обратную связь, смотреть логи и статистику и приоритизировать улучшения.
